# 分布式集群使用说明

## 工作方式

集群协作按配置启用；未启用的旧配置继续使用原有更新流程。每个节点独立运行定时任务，没有固定调度节点。单节点自行更新；多节点先探活，先触发者取得短期执行权后在本机调用 DNS 服务商。200 毫秒竞争窗口内同时触发时，以随机票据选出一个执行者，其他节点跳过本轮。

这是面向少量节点、单操作员的轻量协作机制，不是共识数据库。节点离线不妨碍存活节点自治；网络分区形成互不相见的存活集合时可能重复更新，外部 DNS / Callback 应支持幂等写入。恢复连通后同步最新配置和前缀状态。

## 配置步骤

1. 在每台主机部署此版本，启用 Web 服务。`-noweb` 不适合集群节点。首次加入前设置本机稳定 ID（如 `router-a`）和至少 32 字符的令牌。只需在初始节点设置管理账户，后续同步同一账号密码。
2. 在“集群管理”添加所有节点，包括本机，填写名称、访问地址和令牌。其他主机保存的访问令牌必须对应目标主机的本机令牌。多节点必须填写可互访的本机 URL，支持 HTTP/HTTPS 和反向代理路径前缀；公网使用 HTTPS 或受保护的专用网络。可预先通过 YAML 配置相互信任；尚未建立双向信任时同步和登录占用不会成功。
3. 建立信任后退出其他节点，只在一台节点登录。在配置页面设置 DNS 服务商，并在 IPv4、IPv6 大块内按节点分别编辑启用状态、接口／网卡／命令、IPv6 匹配正则和域名。可以直接修改其他节点的网络配置；命令在对应节点执行。
4. 在独立的“集群管理”页面为该配置启用集群，设置唯一组标识（如 `home`），关联 `router-a,server-b`，设置统一前缀长度和冷却时间。不再设置调度节点。
5. 保存后立即推送完整配置，包括所有 DNS 配置、各节点的网络设置、DNS 凭据、账号密码哈希、Webhook、语言和审计设置，然后由保存节点触发更新。同步失败每 10 秒重试；页面刷新可查看同步错误。仅进程身份（本机 ID、入站令牌）及运行状态／审计文件保持各节点独立。
6. 配置使用稳定 ID；增删改全部同步。配置版本持久化为逻辑计数，冲突按计数和节点 ID 确定胜者；切换节点后等待同步完成再编辑。首次加入前备份已有配置，因为完整同步会覆盖目标节点的配置和账户。数据库设置重启后生效。

节点的所属组字段可为空（允许被多个配置组关联）；非空时限制只能关联到该组。每项配置可关联多个节点，最多配置 128 个节点。

## 按节点配置 IP

配置页面先分 IPv4 / IPv6 两大块，再列出各节点，复用原版表单：是否启用、通过接口／网卡／命令获取、IPv6 匹配正则、Domains。每行一个域名；不可注册域名仍可用冒号分隔子域名与根域名。同一配置内同类型域名不能绑定多个节点。HTTP 请求绑定网卡为该配置共用设置；每个节点的获取网卡可通过下拉框独立选择；列表从对应节点读取，离线时保留原选择。Linux 会读取地址有效期并排序，默认使用有效期最长的 IPv6 地址，可选择具体地址（@1、@2）或填写正则。其他系统在无法读取有效期时保持网卡返回顺序。

IPv6 大块只有一份“自定义 IP 后缀”，含启用开关和 IP 列表，**不在每个节点重复设置**。启用后按上方各节点已配置的 IPv6 域名顺序逐行对应，例如 `::1000`、`::1001`；空行或未填写的行使用对应节点原后缀。停用时全部使用节点自身后缀。只允许主机位，单段最多四位十六进制数，`::10001` 不是合法 IPv6。IPv4 不使用此设置。未显式启用集群的单节点配置也可使用自定义后缀。

访问令牌生成后明文显示，并可在已登录的集群页面重新查看、复制；公开探活接口不返回令牌。

执行者先读取所有存活节点的地址，再分别更新各节点绑定的域名。不存在固定中心；同时触发用随机票据竞争执行权。旧版的指定来源、随机／轮询来源策略仍能读取，以兼容旧 YAML；新表单使用按节点绑定。

`GET /ping` 无需登录，固定返回 `{"status":"ok"}`，不访问配置或数据库。远程探活最多并发 8 个，每个超时 2 秒。`/cluster/ip`、`/cluster/claim`、`/cluster/state` 和 `/cluster/sync` 使用独立 Bearer 令牌及已知节点 ID 验证，并不公开。

## IPv6 前缀变化

前缀长度默认为 64，可设为 1–128，支持 /57、/73 等非整字节长度。自定义后缀必须仅使用主机位，例如 /64 的 `::1234`。同一组中的地址应属于同一个前缀变化域，不能把不同网络的 IPv6 地址混为同组。

**同一配置下全部节点必须属于同一 IPv6 前缀变化域。** 不要把不同网络前缀放进同一配置，否则会相互覆盖 DNS，形成反复更新。首次发现多个冲突前缀或旧前缀长期与当前前缀混杂时，会报错暂停前缀更新，须调整分组。

某节点出现新前缀后，执行者再次探活，保留所有节点已知后缀（或使用全局后缀列表中该域名对应的后缀），更新当前配置的全部 IPv6 域名。离线节点若有缓存后缀仍会更新；缺少后缀则报错等待补齐。IPv4 按各节点自身地址处理。

前缀防抖缓存最后成功前缀、成功时间戳、近期退役前缀及其截止时间。新前缀立即更新；冷却期内收到退役前缀时忽略，普通更新也统一使用成功前缀，防止漏过防抖写回旧地址。默认冷却 60 秒，可在集群页按配置调整；连续快速变化时倍增，最多为基础值四倍，稳定后恢复基础值。冷却结束且全部上报节点一致返回旧前缀时允许真正回退。

状态保存在配置文件旁的 `.cluster-state.json`，释放执行权前同步给存活成员；新执行者先读取最新状态。批次先持久化再执行，仅全部成功后确认新前缀及时间戳。失败或重启后重试未完成批次，提供至少一次执行，Callback 应支持幂等调用。一分钟内相同配置和地址的普通任务会去重，不自动回滚已完成的外部 DNS 更新。

## 集群登录

登录时向所有已配置节点申请同一节点占用：同节点允许多个独立浏览器会话，其他节点不能同时登录。退出一个会话不影响其他会话；最后一个活动会话退出时释放占用。所有节点同步同一账号和密码哈希。

任一成员不可达时拒绝新登录，这不影响存活节点的 DNS 自治。页面每 15 秒续期，会话／节点占用 45 秒到期；关闭页面或崩溃后等待到期再切换。浏览器后台节流可能导致重新登录。新增成员后续期会重新确认全体成员；维护离线成员时需先调整节点配置。

## 默认配置路径

Linux 普通用户新配置为 `~/.config/ddns-go/config.yaml`，root 服务新配置为 `/etc/ddns-go/config.yaml`，保存时创建目录。优先读取上述目录已有配置，并兼容原仓库的 `~/.ddns_go_config.yaml`；不自动移动或删除旧文件。`-c` 和 `DDNS_CONFIG_FILE_PATH` 可显式指定路径。其他系统保留原默认路径。审计数据库和集群状态默认与配置文件放在一起。

## 审计存储

默认 SQLite 文件为 `<配置路径>.audit.db`。可以在集群页面配置驱动和 DSN，或在 YAML 中设置：

```yaml
audit:
  driver: sqlite
  dsn: /var/lib/ddns-go/audit.db
```

审计模块使用 `database/sql` 和无 CGO SQLite 驱动，不需要 SQLite 外部进程。记录采用 UTC 时间；查询页显示浏览器本地时间，并支持配置名称、节点名称、操作类型过滤和分页。

审计包含配置和节点的添加、编辑、删除，登录、退出、设置变更、节点选择、前缀变化和 DNS 更新结果。密码、令牌、DNS 凭据及可能包含凭据的命令和 URL 不记录原文。DNS 更新的前值为执行进程上次成功应用的值，首次执行标为未知，不宣称它是实时查询到的权威 DNS 值。

写入通过 1024 条有界队列异步处理，数据库写入不阻塞 DNS 业务。数据库失败或队列满时会输出服务日志，并在审计查询页显示未持久化事件计数；异常退出可能丢失尚未刷盘的事件。正常停止最多等待 5 秒刷新。此实现不是零丢失的合规审计系统。SQLite 文件和配置文件应存放在仅服务账户可访问的目录，备份时包含数据库及其 WAL 文件。

`audit.Store` 定义 `Append`、`Query`、`Close`，使用 `audit.Register("mysql", factory)` 或 `audit.Register("postgres", factory)` 注册额外适配器。适配器自行处理数据库驱动、连接、建表和 SQL 方言；当前仅内置 SQLite，不会因填写 MySQL/PostgreSQL DSN 自动安装驱动。

```sh
make build test
CGO_ENABLED=1 go test -race ./...
GOARCH=arm64 CGO_ENABLED=0 go build ./...
GOARCH=riscv64 CGO_ENABLED=0 go build ./...
GOARCH=mipsle CGO_ENABLED=0 go build ./...
```

新增测试使用模拟节点和本地模拟 DNS 服务商，覆盖本机执行、并发竞争、单点登录、配置推送和断线恢复、离线节点、前缀变化、失败批次恢复、旧配置兼容、鉴权、表单序列化和 SQLite 持久化。无需真实 DNS 账户。
