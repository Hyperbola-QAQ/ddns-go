# ddns-go 分布式集群扩展

上游 [jeessy2/ddns-go](https://github.com/jeessy2/ddns-go) 负责获取主机的公网 IP，并通过 DNS 服务商更新域名记录。本仓库是个人维护的 fork，面向一人管理多台主机的场景。每台主机采集自己的地址，各节点同步配置，由取得本轮执行权的节点统一更新 DNS。感谢上游作者及贡献者。

扩展包括节点间配置同步、去中心化 DNS 更新、IPv6 前缀协作与防抖、独立自定义后缀域名及审计日志。项目仍处于开发阶段，不提供旧开发版配置的迁移支持。本文说明本 fork 的功能与部署方式。

## 构建与运行

使用 `go.mod` 声明的 Go 版本，在本仓库的 `feature-distributed-cluster` 分支构建：

```sh
git clone --branch feature-distributed-cluster https://github.com/Hyperbola-QAQ/ddns-go.git
cd ddns-go
make build
./ddns-go -l :9876
```

访问 `http://主机地址:9876` 设置管理账户。首次账户设置需在程序启动后 30 分钟内完成。可用 `-c /path/to/config.yaml` 指定配置文件；默认路径见下文。各节点应使用同一版本的本 fork，集群需要开启 Web 服务。

上游 ddns-go 的发布包和 `jeessy/ddns-go` 镜像不包含本仓库新增的分布式功能，请使用本仓库构建的程序。

## 工作方式

集群协作按 DDNS 配置启用；未启用协作时，各节点更新自身绑定的域名。单节点也可启用自定义后缀。每个节点独立运行定时任务，没有固定调度节点。单节点自行更新；多节点先探活，先触发者取得短期执行权后在本机调用 DNS 服务商。200 毫秒竞争窗口内同时触发时，以随机票据选出一个执行者，其他节点跳过本轮。

这是面向少量节点、单操作员的轻量协作机制，不是共识数据库。节点离线不妨碍存活节点自治；网络分区形成互不相见的存活集合时可能重复更新，外部 DNS / Callback 应支持幂等写入。恢复连通后同步最新配置和前缀状态。

## 配置步骤

1. 在每台主机部署此版本，启用 Web 服务。`-noweb` 不适合集群节点。首次启动自动生成并保存 12 字符节点 ID 和访问令牌，本机名称取主机名，ID 保存在 `cluster.nodeid`，管理接口不允许修改。开发阶段不读取旧 `cluster.localid`，也不迁移节点引用或旧配置组状态；旧开发配置请重新创建。只需在发起节点设置管理账户。目标节点可以直接加入，加入成功后使用发起节点的账号和密码登录。
2. 在“集群管理”添加其他节点，只填写访问地址和令牌，保存时自动识别节点 ID 与名称。本机地址默认取当前页面地址，可按实际网络修改。其他主机保存的访问令牌必须对应目标主机的本机令牌。多节点必须填写可互访的本机 URL，支持 HTTP/HTTPS 和反向代理路径前缀；公网使用 HTTPS 或受保护的专用网络。在 A 填写 B 的地址及 B 的令牌并保存后，双方会合并节点拓扑和 DDNS 配置，并同步到各自集群的其他成员，无需再到 B 手动添加 A。须填写 A 可被 B 访问的本机地址。
3. 各节点均可独立登录。在配置页面设置 DNS 服务商。集群节点会自动出现在每个配置的 IPv4、IPv6 区域，无需再次添加节点网络配置；新节点默认禁用两种协议。按节点分别编辑启用状态、接口／网卡／命令、IPv6 匹配正则和域名。可以直接修改其他节点的网络配置；命令在对应节点执行。
4. 在配置管理的 IPv6 区域启用“集群 IPv6 前缀协作更新”，设置前缀长度（默认 64）及冷却时间（默认 60 秒）。每个 DDNS 配置本身就是独立的前缀更新范围，不再填写配置组标识。
5. 保存后立即推送完整配置，包括所有 DNS 配置、各节点的网络设置、DNS 凭据、账号密码哈希、Webhook、语言和审计设置，然后由保存节点触发更新。同步失败每 10 秒重试；页面刷新可查看同步错误。仅进程身份（本机 ID、入站令牌）及运行状态／审计文件保持各节点独立。
6. 配置使用稳定 ID；增删改全部同步。配置版本持久化为逻辑计数，冲突按计数和节点 ID 确定胜者；切换节点后等待同步完成再编辑。首次加入合并双方配置，加入后的普通同步仍传播完整快照（包括删除操作）。数据库设置重启后生效。

## 节点加入与集群合并

**在 A 添加 B 时，A 是本次加入的发起方。** 首次初始化只需在 A 创建管理员账号（启动后 30 分钟内）。B 启动后使用自动生成的节点访问令牌接入。加入成功后，A 的管理员用户名和密码哈希覆盖 B 已有的登录凭据，并随共享配置同步到双方集群的其他成员。B 的节点 ID 和入站令牌继续由 B 管理。

在 A 的“集群管理”中填写 B 的访问地址和 B 的令牌并保存，即可发起加入。名称和 ID 自动识别，B 自动获得 A 的信息；无须在 B 反向添加 A。每台节点都需要提供其他成员可访问的地址，最多支持 128 个节点。

此操作既支持两个独立节点，也支持两个已有集群。例如 A/B 已组成集群，C/D 已组成另一个集群，在 A 添加 C 后，双方的节点拓扑与 DDNS 配置合并，并逐步同步至 A、B、C、D。

合并按稳定 ID 判断对象，具体规则如下：

| 对象或情况 | 合并结果 |
| --- | --- |
| 不同 ID 的 DDNS 配置 | 全部保留；配置名称相同也不会互相覆盖 |
| 相同 ID 的 DDNS 配置 | 视为同一配置，保留双方各自的节点网络设置 |
| 同一配置、同一节点的网络设置冲突 | 以发起方为准；自动生成的空白节点表单不会覆盖对方已有设置 |
| 同一配置的 DNS 服务商、凭据、自定义后缀等共享字段冲突 | 以发起方为准 |
| 全局账号密码、Webhook、语言、审计及公网访问设置 | 统一使用发起方的值；账户变化后需重新登录 |
| 本机 ID、入站令牌、运行状态和审计文件 | 各节点独立保留 |

首次加入采用上述合并规则；加入完成后的普通同步使用完整配置快照，新增、修改和删除都会传播，不会在每次同步时重新合并并恢复已删除的配置。并发编辑按配置版本的逻辑计数及节点 ID 确定胜者，建议等待同步完成后再切换节点编辑。

保存按钮旁会区分“本机已保存”“正在同步”和具体节点同步失败。本机保存成功不代表所有成员已经同步完成；加入请求会保存下来，失败后自动重试，离线成员恢复后通过周期同步补齐。

## 节点在配置页的显示

集群节点会直接显示在每个 DDNS 配置的 IPv4、IPv6 区域，已移除“添加节点网络配置”和配置内“移除此节点”按钮。已有页面可刷新以加载最新节点列表。

新增节点的 IPv4、IPv6 默认均不启用，域名列表为空；现有节点的网络设置保持原值。只需在相应节点下启用协议并填写获取方式和 Domains，无须再次建立节点关联。未使用的节点保持禁用即可；节点拓扑的增删统一在“集群管理”中完成。

## 按节点配置 IP

配置页面先分 IPv4 / IPv6 两大块，再列出各节点，复用原版表单：是否启用、通过接口／网卡／命令获取、IPv6 匹配正则、Domains。每行一个域名；不可注册域名仍可用冒号分隔子域名与根域名。同一配置内同类型域名不能绑定多个节点。HTTP 请求绑定网卡为该配置共用设置；每个节点的获取网卡可通过下拉框独立选择；列表从对应节点读取，离线时保留原选择。Linux 会读取地址有效期并排序，默认使用有效期最长的 IPv6 地址，可选择具体地址（@1、@2）或填写正则。其他系统在无法读取有效期时保持网卡返回顺序。

IPv6 区域显示最近确认的公共前缀，以及各节点最近上报的地址和自身域名。在“自定义后缀组”中，每组只填写一个 IPv6 后缀，可关联多个域名（每行一个）。例如 14 个域名指向同一设备时，建立一个 `::1000` 组即可。页面根据已确认前缀预览合成的 AAAA 地址。域名在组内、组间及节点 IPv6 配置中均不能重复；节点自身域名继续使用节点地址。至少启用一个节点的 IPv6 获取以提供前缀。关闭后缀组后停止更新该组功能关联的域名。旧自定义配置升级时需将原有后缀和域名整理为 `ipv6suffix.groups`，每项包含 `suffix` 和 `domains`。

访问令牌首次启动时自动生成。点击“生成令牌”会显示新令牌，需保存后才生效；刷新页面显示已保存的令牌。已登录的集群页面可以明文查看、复制本机及关联节点的令牌，公开探活接口不返回令牌。

执行者先读取所有存活节点的地址，再分别更新各节点绑定的域名。不存在固定中心；同时触发用随机票据竞争执行权。节点的 IP 获取方式和 Domains 在配置管理中分别设置。

`GET /ping` 无需登录，固定返回 `{"status":"ok"}`，不访问配置或数据库。远程探活最多并发 8 个，每个超时 2 秒。`/cluster/ip`、`/cluster/claim`、`/cluster/state` 和 `/cluster/sync` 使用独立 Bearer 令牌及已知节点 ID 验证，并不公开。首次识别节点的 `/cluster/identity` 与加入接口 `/cluster/join` 通过目标节点的 Bearer 令牌鉴权，无需预先双向添加。

## IPv6 前缀变化

前缀长度默认为 64，可设为 1–128，支持 /57、/73 等非整字节长度。自定义后缀必须仅使用主机位，例如 /64 的 `::1234`。同一配置的地址应属于同一个前缀变化域。

**同一配置下全部节点必须属于同一 IPv6 前缀变化域。** 不要把不同网络前缀放进同一配置，否则会相互覆盖 DNS，形成反复更新。首次发现多个冲突前缀或旧前缀长期与当前前缀混杂时，会报错暂停前缀更新，须拆分 DDNS 配置。

某节点出现新前缀后，执行者再次探活，保留各节点地址的已知后缀，并将新前缀与独立自定义后缀逐项拼接，更新当前配置中已启用的节点 IPv6 域名和自定义域名。离线节点若有缓存后缀仍会更新；缺少后缀则报错等待补齐。IPv4 按各节点自身地址处理。

前缀防抖缓存最后成功前缀、成功时间戳、近期退役前缀及其截止时间。新前缀立即更新；冷却期内收到退役前缀时忽略，普通更新也统一使用成功前缀，防止漏过防抖写回旧地址。默认冷却 60 秒，可在配置管理的 IPv6 区域调整；连续快速变化时倍增，最多为基础值四倍，稳定后恢复基础值。冷却结束且全部上报节点一致返回旧前缀时允许真正回退。

状态保存在 `<配置文件路径>.cluster-state.json`，释放执行权前同步给存活成员；新执行者先读取最新状态。批次先持久化再执行，仅全部成功后确认新前缀及时间戳。失败或重启后重试未完成批次，提供至少一次执行，Callback 应支持幂等调用。一分钟内相同配置和地址的普通任务会去重，不自动回滚已完成的外部 DNS 更新。

## 集群登录

各节点允许独立登录及多个浏览器会话，不再申请集群登录占用。新增或离线节点不影响登录和已有会话。会话按登录 Cookie 的有效期过期，退出只注销当前会话；同步账号密码发生变化时需重新登录。

## 默认配置路径

Linux 普通用户新配置为 `~/.config/ddns-go/config.yaml`，root 服务新配置为 `/etc/ddns-go/config.yaml`，保存时创建目录。优先读取上述目录已有配置，并兼容原仓库的 `~/.ddns_go_config.yaml`；不自动移动或删除旧文件。`-c` 和 `DDNS_CONFIG_FILE_PATH` 可显式指定路径。其他系统保留原默认路径。审计数据库和集群状态默认与配置文件放在一起。

## 审计存储

默认 SQLite 文件为 `<配置路径>.audit.db`。可以在集群页面配置驱动和 DSN，或在 YAML 中设置：

```yaml
audit:
  driver: sqlite
  dsn: /var/lib/ddns-go/audit.db
```

审计模块使用 `database/sql` 和无 CGO SQLite 驱动，不需要 SQLite 外部进程。记录采用 UTC 时间；查询页显示浏览器本地时间，并支持配置名称、节点名称、操作类型过滤和分页。

审计包含配置和节点的添加、编辑、删除，登录、退出、设置变更、节点选择、前缀变化和 DNS 更新结果。密码、令牌、DNS 凭据及可能包含凭据的命令和 URL 不记录原文。DNS 更新的前值为执行进程上次成功应用的值，首次执行标为未知，不宣称它是实时查询到的权威 DNS 值。

写入通过 1024 条有界队列异步处理，数据库写入不阻塞 DNS 业务。数据库失败或队列满时会输出服务日志，并在审计查询页显示未持久化事件计数；异常退出可能丢失尚未刷盘的事件。正常停止最多等待 5 秒刷新。此实现不是零丢失的合规审计系统。SQLite 文件和配置文件应存放在仅服务账户可访问的目录，备份时包含数据库及其 WAL 文件。

`audit.Store` 定义 `Append`、`Query`、`Close`，使用 `audit.Register("mysql", factory)` 或 `audit.Register("postgres", factory)` 注册额外适配器。适配器自行处理数据库驱动、连接、建表和 SQL 方言；当前仅内置 SQLite，不会因填写 MySQL/PostgreSQL DSN 自动安装驱动。

make build test
